# CoScience：科研证据闭环核心设计

日期：2026-09-05

状态：核心交互已获用户确认；本文是首次书面整理，供用户审阅。工程技术方案不在本次确认范围内。

## 1. 产品定位与范围

构建面向个人 AI 科研的 harness，采用左侧项目与对话、中间对话、右侧工作控制台的布局。

新建对话有四种类型：Idea 与方向讨论、实验、画图、论文写作。实验在项目下单独折叠，并明确分为“复现与小规模验证”和“正式实验”两个独立分组。画图和写作通常在实验接近完成时开展，本次优先定义 Idea 与实验之间的证据闭环。

调研控制台包含 Reference 泛读材料库和 Baseline 精读材料库。后者支持追溯论文实验设置、参数、官方代码以及结果图的生成依据。

实验控制台的后续能力包括 SSH、GPU 监控、实验进度、磁盘产物管理，以及用户配置的保存镜像和关闭实例等完成后策略。本文件不确定这些能力的平台适配和实现细节。

## 2. 已确认的核心规则

1. 科研围绕假设、理论推导和实验证据推进。实验通常提供有条件的支持或反证，不能自动等同于证明整个假设。
2. Idea 窗口定义若干实验节点，提前说明结果符合预期、不符合预期或不足以判断时，分别可能意味着什么。
3. 实验窗口执行节点，将阶段结果连同证据返回 Idea 窗口。
4. AI 解释结果并提出后续分支；用户手动选择分支。AI 不自动决定修改假设、转向或宣告方向失败。
5. 主控将用户选定的分支组织为实验节点，再交给子任务执行。
6. 实验可靠性验收与科研意义判断分开：前者回答实验是否有效，后者回答结果意味着什么。

## 3. 共享记录

下列字段是对已确认交互的设计展开，用于实现与审阅，不代表用户逐项指定的数据结构。

| 记录 | 必需内容 | 责任窗口 |
| --- | --- | --- |
| 假设版本 | 研究问题、假设、理论依据、适用条件、可验证预测 | Idea |
| 实验节点 | 关联假设版本、验证问题、前置节点、实验方案、预期结果、验收标准 | Idea 定义，实验主控细化 |
| 实验运行 | 所属节点、代码版本及未提交修改、数据版本、参数、环境、随机种子、状态、产物位置 | 实验 |
| 证据 | 原始指标、日志、分析结果、来源运行、已知局限 | 实验 |
| 验收记录 | 通过、补充证据或不通过，以及检查依据和问题 | 实验主控 |
| 结果解释与候选分支 | 对应预测、证据支持程度、替代解释、下一步实验、预计成本及估计依据 | Idea |
| 用户决策 | 用户选择、关联证据与假设版本、用户给出的理由、时间 | Idea 中记录用户选择 |

实验节点与运行分开：同一个节点可以有多次重复、重试和参数配置。失败或不符合预期的运行保留记录。

理论推导保留假设、推导步骤和来源；文献事实、官方代码行为、AI 推断和未确认信息应明确区分。

## 4. 窗口读写与上下文

- Idea：读取文献、假设、已验收证据与历史决策；产出假设草稿、节点草稿、结果解释和候选分支。用户选择后记录正式决策。
- 实验主控：读取已确认节点及相关研究目的；细化执行任务，分配模型与资源，汇总证据并进行可靠性验收。
- 复现与小规模验证主控：管理数据与管线验证、Baseline 复现、组件增删和低成本 Idea 验证。其结果主要回答“实验系统是否可信”和“Idea 是否值得正式投入”，不能直接升级为论文主张。
- 正式实验主控：只接收用户确认的晋级决策和正式实验方案，管理公平对比、多随机种子、消融、鲁棒性和最终结果。它读取复现与小规模验证的冻结证据，但不改写其历史结果。
- 实验子任务：读取完成本任务所需的目标、约束、材料和验收条件；产出代码、运行记录、结果及问题报告。不得自行改变研究假设或采用未选定的研究分支。
- 画图：读取研究意图与有来源的结果；产出图表计划、可重跑绘图代码及图表来源映射。
- 写作：读取已确认的假设、方法、结论、图表和引用；产出文稿及论断到证据的映射。

共享记录独立于聊天摘要存续。窗口上下文按任务引用具体记录与版本；用户能够查看和调整。假设或实验方案更新时保留历史证据，并标记需要复核的下游解释、图表与文稿。

## 5. 节点状态与验收

正常流程：

```text
草稿 → 用户确认 → 执行中 → 待验收 → 已验收 → Idea 待判断
                                                    ↓
                                  用户选择后续分支或结束当前方向
```

“用户确认”表示明确确认节点及允许的执行范围。选定研究分支后，如果主控细化了新的实验方案，仍应展示该节点供确认；不把分支选择解释为任意实验的无限授权。

主控验收检查：

1. 代码、数据、环境与参数可追溯。
2. 实际执行符合节点定义，指标和图表可追溯到真实产物。
3. 实际结果与预期逐项对照，报告异常、失败运行和局限。
4. 证据足以提交 Idea 判断，或明确说明尚缺什么。

验收通过表示实验有效，不表示假设成立。与预期相反的有效实验也可以通过验收。

### 实验分组与晋级

项目左侧的实验区域保持以下独立结构：

```text
实验 ▾
  复现与小规模验证 ▾
    管线验证主控
    Baseline 复现
    Idea 小规模验证
    组件增删与机制验证
  正式实验 ▾
    正式实验主控
    主结果对比
    消融实验
    鲁棒性与边界实验
```

两组使用不同的控制台视图和上下文入口。复现与小规模验证可以产生“建议晋级”报告，但不能自动创建正式实验。晋级至少需要：相关运行已验收、Baseline 的复现差异已有解释或明确记录、Idea 的预测与小规模证据已对齐、正式实验方案已由用户确认。用户确认后，系统将一份冻结的晋级记录交给正式实验主控；此前的探索运行仍保留在原分组。

从 Baseline 出发的增添、删除或替换组件，必须记录变更动机、理论预测、固定条件、对照对象和预期观察。性能提升但机制预测不成立时，结果仍可验收，但解释标记为不确定，不能自动写成论文因果结论。

补充证据：记录缺口并生成补充任务草稿；已有授权内的机械修复或重试可由主控处理，涉及新研究分支时等待用户选择。

不通过：保留失败依据，修正后重新执行和验收，不作为已验证的研究结论。

运行失败、中断与连接丢失记录在运行层。连接丢失不等同于远程实验停止；状态未核实时显示未知，不直接重复启动。

## 6. 结果返回 Idea 的交互

每次回传包含：节点目标、预期与实际结果、证据链接、验收结果、局限，以及候选解释。

候选分支显示：触发结果、支持证据、未解释现象、预计新增成本及不确定性、拟创建节点。用户可以选择、修改、自定义分支或暂不决定。等待期间，不执行尚未选择的分支。

例如：假设 H1 预测方法在低数据量条件下更有效。节点 N1 比较多个数据规模下的方法与 baseline。若收益只出现在一个规模，AI 可以建议增加重复运行、检查数据差异、限定假设适用范围或放弃该方向。实际采用哪条分支由用户决定。

## 7. 实现时的验收场景

- 有效但不符合预期的结果能够通过实验验收，并回到 Idea 等待用户判断。
- 未选择的候选分支不会启动实验。
- 新窗口能基于共享记录恢复研究状态，不依赖原始聊天全文。
- 同一节点的失败、重试和重复运行均可追溯，不能只保留最好结果。
- 假设更新后，历史结果仍绑定原版本，下游内容出现复核标记。
- 连接中断不会被误认为实验完成或直接触发重复执行。

## 8. 后续设计边界

本次不选择桌面框架、Agent 引擎、模型供应商、数据库或远程执行协议，也不确定自动验收的具体检查器。

后续分别设计：核心记录与持久化、Idea/实验交互、复现与小规模验证、正式实验、任务执行与模型调度、远程资源管理，最后扩展画图和写作。GPU 空闲本身不能作为实验完成或关闭实例的唯一依据；资源策略需独立核验结果保存与其他任务依赖。
